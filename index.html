診斷

問題、做對的地方、觀察

影片只有 1 次 Launch，以下都是「這一次」的狀況，還不能確認是不是習慣。多拍幾次就能看出是不是每次都這樣。

主要問題 · Pull 時 Launcher 被帶走 B估算 · 這項當參考

  • Setup（F20–F37）Launcher 只晃 1.9 px RMS，從 Pull 開始到 Release 卻移動 76–80 px（0.37–0.38 × 肩寬）。
  • 方向：Pull 手往畫面左上（約 35°），Launcher 往畫面右上（右 62 px、上 44 px），兩手往反方向分開。
  • Launcher 是持續、平順地移動（Release 前後抖動只有 1.1 px），比較像整隻 Launcher 手跟著身體轉，不是握不穩。
  • Release 後 Launcher 又移動約 78 px（到 F90），代表手沒有停在原位。

為什麼要改：Setup 時對好的位置和角度，到 Release 時已經不一樣了。每次被帶走的量如果不同，Release 的位置和角度就很難每次一樣。

做對的地方

  • Setup 很穩：F20–F37 Launcher 中心晃動 0.009 × 肩寬（1.9 px RMS）。B估算
  • Release 附近沒有亂抖：F58–F69 抖動 1.1 px RMS。握力和手腕是穩的，只要把位置固定住就好。B估算
  • 身體有參與：肩寬投影從 Setup 到 Release 縮到 0.46×，髖只縮到 0.69×，上半身轉得比髖多。軀幹長度幾乎不變，所以這是轉身，不是遠離鏡頭。轉身大約從 F28–F30 開始，比拉動手離開 Launcher 早約 0.3 s。B估算
  • 低位放出：Launcher 貼近 Stadium 靠球員側的外緣放出。C視覺判讀 · 無可靠數值

觀察（只拍到 1 次，不列為主要問題）

  • Pull 期間（約 F42–F60）右腳往畫面左側移出，下盤有移動。下半身大多被 Stadium 擋住。C視覺判讀 · 無可靠數值
  • Pull 期間 Launcher 有可見的轉動，但 Launcher 外形接近方形又被手指擋住，不給角度數字。C視覺判讀 · 無可靠數值
  • String 在 F42–F50 可隱約看到，太細太糊，無法量線角和拉出長度。C視覺判讀 · 無可靠數值
練習 1 · 空拉

Launcher 手貼點

  1. 不裝 Beyblade，Launcher 手的前臂或手肘靠在身體或桌邊。
  2. 照平常的方式拉 10 次，手機放同一個位置錄影。
  3. 看 Launcher 有沒有離開起點。目標：拉完還停在原位。
練習 2 · 參考點

盯住一個對齊點

  1. 在 Stadium 邊緣貼一小段膠帶當參考點。
  2. Setup 時讓 Launcher 前緣對準膠帶。
  3. Release 後馬上看：Launcher 還對著膠帶嗎？偏了就降低拉的速度再試。
練習 3 · 分段加速

先穩、再快

  1. 50% 力道拉 5 次，確認 Launcher 不動。
  2. 75% 力道 5 次，再來全力 5 次。
  3. 哪一段 Launcher 開始被帶走，就停在那個力道多練。
Launch-to-Launch

一致性比較 · BEST LAUNCH

不適用 · 影片只有 1 次 Launch

整支 29 秒的影片裡只有一次發射（F39–F64），其餘是 Beyblade 在 Stadium 裡旋轉。最穩定／最不穩定 Launch 和重複性都需要至少 2 次 Launch 才能比較。下次一支影片連續錄 5–10 次，這一區就會自動有排名和疊圖比較。

怎麼拍可以解鎖完整分析

  • 全身入鏡：頭、雙手、雙腳都在畫面內，拉動手拉到底也不能出畫面。這次 Pull 最快的那段和 Release 後的身體都在畫面外。
  • 鏡頭放側面或斜前 45°，高度約在腰部：這次鏡頭在 Stadium 對面、很低，Stadium 擋住下半身。
  • 用腳架固定：這次開頭 0.7 秒手機有移動。
  • 開 60 fps 以上（有 120/240 fps 慢動作更好）：才能量 Pull 峰值和 Release timing。
  • 同一支影片連續錄 5–10 次 Launch：才能做一致性比較和選出 BEST LAUNCH。
  • 直接傳原檔：WhatsApp 會重新壓縮畫質。
